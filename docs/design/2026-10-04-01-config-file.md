# Design: config file

## Purpose

Allow tweaking settings on a live system without editing the
systemd units, and keep values that must change in lockstep
visible in a single file.

## Format and location

- `/etc/sonda/config.toml`, shipped with every option commented
out at its default value. TOML is a good enough approximation of
a git-like config file.

- Sections follow the component path (`[inetd.ptnop]`,
`[spool.gc]`), with hyphens only inside key names (`max-age`).
A dotted path survives adding siblings or children on either side
better than names like `inetd-ptnop`.

## Precedence

- Code defaults (`config.Defaults()`), then the file
(`config.ReadInto`), then command line flags.

- Defaults and reading are separate functions, so reading more
than one file later only means calling `ReadInto` again.

- Because flags win, the systemd units pass no flags for settings
that live in the file.

## Errors

- A missing file is not an error: the defaults apply.

- Unknown keys are an error, so a typo does not silently fall back
to the default.

- Durations must be strings (`"6h"`): the TOML decoder would read
a bare `6` as six nanoseconds.

- Commands report config errors only after parsing flags, so
`-h` and `--help` work even with a broken file.

## What is not in the file

- Paths that systemd units or maintainer scripts also depend on:
the spool directory, the metrics directory, and the
`sonda-inetd-ptnop` socket. Changing them in the file alone would
break the installation. They are constants in `internal/config`,
and a bind mount or a symlink relocates a directory. See
`2026-10-04-00-data-types.md`.

- So the file holds only settings that sonda alone reads, and only
the commands that use one of those settings read it: today
`sonda spool gc` (`spool.gc.max-age`) and `sonda-inetd-ptnop`
(`inetd.ptnop.idle-timeout`).
