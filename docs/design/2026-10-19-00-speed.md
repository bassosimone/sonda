# Design: speed measurements

## Purpose

Measure download speeds (e.g., `https_speed.yml`) without
flooding the spool with per-read events.

## Logging: `optimize=speed`

- Keep all info level events, drop debug events except for
`readDone` and `writeDone`, and keep at most one of those every
250 ms per direction. Events with an error are always kept.

- `readDone` and `writeDone` carry the cumulative byte totals, so
the kept samples still allow offline analysis (e.g., stalls) on
the archive.

- A 100 MiB download over h2 went from ~40k events (~500 KB
gzipped) to 72 events (~8 KB).

## Metric: `sonda_ptnop_conn_avg_speed_bits_per_second`

- `etl-ptnop-prom` computes it, since the archive ETL only archives.

- One observation per connection and direction with nonzero bytes:
bytes times 8 divided by the time between `connectDone` and
`closeStart`. This includes idle time before close and TLS/h2
overhead.

- Rejected: time-to-N-bytes marks, interpolating between samples
(stalls make it optimistic), timing from the start of the body
stream.

## Known limitations

- No workflow label, so speeds from different workflows mix
when they hit the same destination.
